### panorama stitching 
 creating a larger image  by aligning two images of the same scene
 - The two images may be aligned by estimating a homography, which requires at least 4 correspondences (more is better)
 - Find “salient points” independently in the two images
 - Compute a local “description” for each salient point
 - Compare descriptions to find matching pairs
 - once you have 4 matches you can stitch the image together

## Local Invariant feature
being able to map two points of two different images if they are the projection of the same 2d point.
several computer vision tasks deal with finding a "Corresponding Points" between two (or more) images of scene
- correspondences = imagese wich are the projection of the same 3d point in different views of the scene
- establishing correspondances may be difficult as these points may look different in the differnt views

### local invariant features paradigm
the first step is to identifiy sailient points 
the next step is to define  descriptors of the points we have selected based on the region around that point
and then we can match the descriptors between the images

the problem when matching images is that we have to be invariant to several factors:
- illumination invariance
- rotation invariance
- scale invariance

![[Pasted image 20261012113645.png]]

### properties of good detectors/descriptors
Detector:
- repeatability: indipendently of the transformation that the image undergoes we always have to be able to find the same keypoints
- saliency: it should finde keypoints sourrounded by informative patterns to be able to have a descriptor that is effective

Descriptor:
- distinctiveness vs. robustness : distinctive means that indipendently of the transformations the signature should still match. the description algorithm should capture the salient information around a keypoint, so to keep important tokens and disregard changes due to nuisances (e.g. light changes) and noise
- compactness: the descriptor should be as coincise as possible, to minimize memory occupancy allow for efficient matching



### interest points vs edges
can edges be found repeatably across different images?
ar these points easily identifies across different images?
Edge pixels can be hardly told apart as they look very similar along the direction perpendicular to the gradient
![[Pasted image 20261012114457.png]]
so using edges as salient points then means that we will not be able to reliably match two keypoints together.
Corners can be used to define peculiar salient points

### moravec Interest point detector
corners are points where you sense a change of intensity in all directions
the cornerness at p is given by the minimum squared difference between the patch centered at p and those centered at its 8 neighbours
![[Pasted image 20261012115529.png]]

### Harris corner detector
still taking squares of differences, but using a continous formulation
shifting the whole image with a generic infinitesimal shift
- w(x,y) is a window set to 1 around the pixel under evaluation and 0 in all the image 
- in the end consider only the pixel around the x,y position
